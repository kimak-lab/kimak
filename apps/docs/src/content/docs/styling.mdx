The public styling API is `data-scope`, `data-slot`, and `data-state`. Treat those as semver. Product `<Button>` takes `variant` and `size` and writes `data-variant` / `data-size` on the host. Neither is a machine prop.

<Callout>
  If a className, hex color, or theme token lands in `@kimak/core` or a headless adapter, it is a bug. Look lives in `@kimak/tailwind` (optional plugin) and in your CSS.
</Callout>

## Anatomy selectors

```css
[data-scope="button"][data-slot="root"][data-variant="outline"] { }
```

Product sugar takes `variant` / `size` and writes the same `data-*`:

```tsx
<Button variant="outline" size="sm">Save</Button>
```

`size` is `xs` | `sm` | `md` | `lg` | `icon-xs` | `icon-sm` | `icon` | `icon-lg`. Omit it for the `md` default.

Button `variant` is `default` | `secondary` | `outline` | `ghost` | `destructive` | `link`.

Icon spacing is `data-icon="inline-start"` | `"inline-end"` on children.

## Tokens

Override raw tokens after importing `theme.css`:

```css
@import "tailwindcss";
@import "@kimak/tailwind/theme.css";
@plugin "@kimak/tailwind";

:root {
  --primary: oklch(0.55 0.2 264);
  --primary-foreground: oklch(0.985 0 0);
  --radius: 0.5rem;
}
```

Loading spinner motion stays in the Tailwind keyframes. Optional JS press motion is `@kimak/motion-gsap` bound by `@kimak/ui-*`. Named recipes are the product `motion` prop (`press` default); they are not `data-variant`.

## Links that look like buttons

Apply `buttonAttrs()` on an `<a>` when you only need the look. Compose the machine onto a link with React `render={<a href />}` or Vue/Svelte `as="a"` — adapters omit native button attrs on the anchor.

```tsx
import { buttonAttrs } from "@kimak/ui-react";

<a href="/docs" {...buttonAttrs({ variant: "outline" })}>
  Docs
</a>
```

`className` on a part is a host DOM prop, not a machine prop. Adapters concatenate it with any class from `render`.
